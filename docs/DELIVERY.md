# گزارش تحویل مرحله‌ای BERJIS

این تحویل، هسته یکپارچه و قابل اجرای DEMO است. تکمیل هسته آزمایشی با تکمیل تمام بندهای سامانه تجاری یا آماده‌بودن برای دریافت وجه واقعی برابر نیست.

## فاز ۱ — معماری، طراحی و صفحات

فایل‌ها: `docs/ARCHITECTURE.md`، `prisma/schema.prisma`، `src/app`، `src/components`، `public`، `components.json`.

قابلیت‌ها: رابط فارسی RTL با Vazirmatn محلی، هویت سرمه‌ای/طلایی، طراحی واکنش‌گرا، Next Image، Lucide، فرم‌های reusable، کامپوننت Button مبتنی بر Radix/shadcn، انیمیشن، skeleton، پیام خطا و حالت خالی. خانه، جستجو، جزئیات خدمت، مجله/مقاله، درباره، تماس، ویزا، FAQ و شرایط به مسیرهای واقعی متصل‌اند. جستجو تقویم شمسی، شهر/فرودگاه، تعداد، رفت‌وبرگشت و چندمسیره دارد. فیلتر قیمت/ایرلاین/زمان و ستاره/امکانات هتل و مرتب‌سازی فعال‌اند. تصاویر الهام‌بخش‌اند؛ دقت تصاویر قراردادی یا SEO تجاری ادعا نمی‌شود.

تست‌ها: مشاهده دسکتاپ و موبایل با Chromium، منوی موبایل، تقویم، نبود overflow افقی، نبود خطای JavaScript و اسکن خودکار WCAG برای خانه/جستجو/ورود. این اسکن تأیید جامع دسترس‌پذیری یا Core Web Vitals نیست.

باقی‌مانده: کلاس‌های پروازی متنوع، تفکیک قیمت کودک/نوزاد، تکمیل محتوای واقعی، نرخ‌ها و اتاق‌های قراردادی، نقشه تعاملی کامل و تصاویر دقیق با مجوز.

## فاز ۲ — بک‌اند، دیتابیس و هویت

فایل‌ها: `src/server/{db,security,validation,errors,redis,transaction}.ts`، migrationهای `prisma/migrations`، `scripts/migrate.ts`، `src/app/api/v1/[...path]/route.ts`.

قابلیت‌ها: PostgreSQL واقعی، Prisma با adapter رسمی pg، Redis واقعی، migration تراکنشی با checksum و قفل advisory، schema دارای رابطه/unique/index/check constraint، نشست opaque هش‌شده، کوکی HttpOnly، رمز scrypt، نقش‌های شش‌گانه، کنترل مالکیت، Origin/CSRF، Zod، محدودسازی درخواست و رمزگذاری AES-GCM مدرک. APIها داده حساس را برنمی‌گردانند. CSP دارای nonce است و unsafe-eval فقط در توسعه فعال می‌شود.

تست‌ها: نشست/مالکیت/RBAC، منع ارتقای نقش مشتری، منع درخواست cross-origin، تغییر نقش مجاز همراه audit، عدم افشای مدرک و رمز، رمزگذاری و بررسی امضا. دیتابیس تست از دیتابیس توسعه جداست.

باقی‌مانده: OTP، تأیید ایمیل/موبایل، بازیابی رمز، MFA مدیر، مدیریت دستگاه/نشست‌ها، گردش‌کار حذف حساب و سیاست حقوقی نگهداری داده.

## فاز ۳ — چرخه فروش و بازیابی آزمایشی

فایل‌ها: `src/server/services/{catalog,reservations,payments,fulfilment}.ts`، `src/server/adapters`، `src/server/worker.ts`، صفحات checkout/payment/orders.

قابلیت‌ها: جستجوی کاتالوگ از دیتابیس با cache، بازبینی قیمت سمت سرور، نگهداری ۱۵ دقیقه‌ای ظرفیت، رزرو اتمیک تمام مسیرها یا شب‌های اقامت، idempotency، جداسازی وضعیت پرداخت/رزرو/صدور، verification مستقل از payload callback، HMAC و deduplication رویداد، outbox پایدار و BullMQ، انقضا و آزادسازی دقیق ظرفیت، صدور idempotent DEMO پس از تأیید، تأیید دستی تور، درخواست کنسلی و استرداد آزمایشی، اعلان داخل حساب و دریافت سند متنی DEMO.

تست‌ها: رقابت بر سر آخرین صندلی، هتل با شب‌های هم‌پوشان، rollback کل برنامه سفر، retry هم‌زمان رزرو/callback، دست‌کاری مبلغ/واحد پول، callback پیش از نتیجه قطعی درگاه، رقابت انقضا با پرداخت، پرداخت پس از لغو، صدور ناموفق و استرداد، عدم دریافت سند سفارش ناموفق/لغوشده و عدم آزادسازی دوباره ظرفیت، deadlock واقعی دیتابیس با rollback/retry و جداسازی cache محیط تست. مسیر UI خرید پرواز، هتل، تور و رفت‌وبرگشت نیز تست شده است.

باقی‌مانده: API جستجو/reprice/hold/issue واقعی، سیاست شکست جزئی چند تأمین‌کننده، قرارداد fare/rate، PNR و شماره بلیط واقعی، callback/verify/refund بانکی واقعی، PDF/واچر رسمی، اطلاع‌رسانی خروجی پیامک و ایمیل. هر سند فعلی صریحاً DEMO است؛ نهایی‌سازی mock هیچ اعتبار سفر ایجاد نمی‌کند.

## فاز ۴ — پنل مشتری و مدیریت

فایل‌ها: `src/components/{account,admin,order-details}.tsx`، APIهای admin/customer، `scripts/promote-admin.ts`، `scripts/retry-job.ts`.

قابلیت‌ها: سفارش‌های مشتری و تاریخچه، اطلاعات مسافران، پیگیری استرداد، اعلان ماندگار و تیکت/پاسخ، پنل با دسترسی مستقل نقش‌ها، آمار و نمودار بر اساس داده دیتابیس، سفارش‌ها/مسافران/وضعیت‌ها، تأیید دستی، ایجاد/ویرایش/انتشار تور، ویرایش هتل و موجودی روزانه، کنترل کاهش ظرفیت، خروجی CSV، تغییر نقش، ویرایش مقاله، وضعیت تأمین‌کننده و audit. مدیر پیش‌فرض و رمز عمومی seed نمی‌شود.

تست‌ها: ممنوعیت پنل/API مدیریت برای مشتری، ایجاد تور و خروجی مالی در مرورگر، ثبت/حذف مسافر و ثبت تیکت، رویدادهای مدیریت و تفکیک دسترسی حسابدار.

باقی‌مانده: مدیریت کامل بنر/صفحات/media/SEO، مدیریت قرارداد هتل، اتصال و پیکربندی امن تأمین‌کنندگان واقعی، دفتر کل کمیسیون/تسویه/مغایرت بانکی، XLSX بومی، صفحه‌بندی کامل گزارش‌های بسیار بزرگ، گردش کارهای چندمرحله‌ای مالی. CSV فعلی گزارش عملیاتی DEMO است و صورت‌حساب رسمی نیست.

## فاز ۵ — سرویس‌های واقعی

فایل آماده: قراردادهای TypeScript در `src/server/adapters/contracts.ts` و پیاده‌سازی قابل تست در `demo.ts`.

وضعیت: **انجام نشده؛ وابسته به تأمین‌کننده و قرارداد واقعی.** هیچ endpoint یا اعتبارنامه‌ای حدس زده نشده و LIVE بدون adapter رد می‌شود. برای ادامه، مشخصات و sandbox تأمین‌کنندگان و درگاه مجاز، قراردادهای تجاری، کانال پیامک/ایمیل و سیاست‌های قانونی لازم‌اند. کلیدها باید در تنظیمات امن محیط وارد شوند، نه در چت یا Git. یک interface به‌تنهایی adapter تجاری تکمیل‌شده نیست.

## فاز ۶ — اعتبارسنجی و استقرار

فایل‌ها: `tests/booking.test.ts`، `tests/e2e/booking.spec.ts`، `Dockerfile`، composeها، `docs/PRODUCTION.md`، `.env.example`، اسکریپت setup و ابزارهای build.

نتایج قطعی ثبت‌شده:

- ۴۳ تست سرویس/API روی PostgreSQL مجزا گذشت؛ تست صفر یا skip به‌عنوان موفق شمرده نشده است.
- ۱۰ تست مرورگری خرید، ابزارها و دسترس‌پذیری روی build تولیدی گذشت.
- اسکن مستقل خودکار WCAG برای خانه، جستجو و ورود پس از رفع کنتراست گذشت.
- TypeScript و build تولیدی Next.js و bundleهای worker/migration/seed موفق شدند.
- endpoint سلامت، PostgreSQL، Redis و heartbeat worker را تأیید کرد.
- `npm audit` در dependency tree قفل‌شده فعلی، صفر مورد شناخته‌شده گزارش کرد؛ این نتیجه جایگزین بررسی امنیت نیست.

اسکریپت `npm run setup` شامل نصب مجدد frozen، migration و seed واقعاً دوباره اجرا شد و داده‌های موجود را حفظ کرد. دستورهای نصب و startup در پیش‌نویس تنظیمات محیط ذخیره شدند؛ ذخیره پیش‌نویس، انتشار محیط یا تأیید بازیابی در یک task جدید نیست. نتیجه نهایی image و تست داخل کانتینر در ادامه ثبت می‌شود.

انتشار عمومی، load test چندنمونه‌ای، penetration test، آزمون بازیابی backup، بررسی حقوقی/مجوزها و تأیید sandbox رسمی تأمین‌کننده/درگاه انجام نشده‌اند. راهنمای استقرار baseline ارائه شده است؛ سامانه هنوز آماده دریافت وجه واقعی نیست.

### نتیجه نهایی بسته‌بندی و اجرا

- image نهایی `berjis:onboarding` از سورس فعلی ساخته شد؛ runtime با کاربر غیرریشه `node` اجرا شد.
- migration و seed از bundle داخل همان image اجرا شدند؛ migration اعمال‌شده تغییر نکرد و seed موجودی/کاتالوگ را بدون reset داده حفظ کرد.
- وب‌سرور و worker به‌صورت دو کانتینر جدا اجرا شدند. worker بیرون کانتینر هنگام smoke test متوقف بود؛ مسیر ثبت‌نام، جستجو، رزرو ظرفیت، پرداخت موفق آزمایشی، تأیید تأمین‌کننده، صدور و دریافت سند DEMO توسط همین کانتینرها گذشت (`tests/container-smoke.ts`).
- ۴۳ تست سرویس/API و ۱۰ تست مرورگری روی آخرین build موفق شدند؛ تست deadlock واقعی، رقابت callback/expiry، جداسازی Redis تست و rollback چندمسیره نیز اجرا شدند.
- دور موقت خطای ENOSPC در ساخت هم‌زمان Docker/مرورگر با پاک‌کردن کش‌های ساخته‌شده در این کار و کاهش runtime به یک COPY رفع شد؛ تست مرورگر پس از آزادشدن فضا دوباره کامل و موفق اجرا شد. خطا پنهان یا به‌عنوان موفق شمرده نشد.
- fixtureهای حساب/سفارش/تور از اجراهای مرورگری و smoke test پاک شدند؛ هیچ مدیر تست با رمز مشترک برای استفاده بعدی باقی گذاشته نشده است. کاتالوگ اولیه ۴۴ محصول DEMO است.
- کانتینرهای موقت smoke متوقف شدند و اجرای معمول وب‌سرور/worker برای محیط توسعه باقی ماند. این بررسی، انتشار عمومی یا بازیابی snapshot در یک task جدید را اثبات نمی‌کند.

محدودیت مبلغ فعلی DEMO: مبلغ کل سفارش حداکثر ۲٬۰۰۰٬۰۰۰٬۰۰۰ ریال است. برای مقیاس تجاری و مبالغ بالاتر، تغییر ستون‌های مبلغ از Int به bigint/decimal و قرارداد مناسب API هنوز لازم است. محدودیت‌ها و کارهای باقی‌مانده فازها، بخشی از این تحویل‌اند و نباید قابلیت تجاری تکمیل‌شده تلقی شوند.
