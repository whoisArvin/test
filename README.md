# برجیس | BERJIS

پلتفرم فارسی و RTL رزرو سفر با Next.js App Router، TypeScript، PostgreSQL/Prisma، Redis و BullMQ.

**این نسخه یک سامانه یکپارچه آزمایشی است؛ آماده فروش تجاری نیست.** جستجو، رزرو، پرداخت، صدور و استرداد به‌صورت DEMO اجرا می‌شوند. هیچ بلیط، واچر، پرداخت بانکی یا تعهد سفر واقعی ایجاد نمی‌شود.

## اجرای توسعه

پیش‌نیاز: Node.js 24 (حداقل 22.12)، npm، Docker و Docker Compose. کاتالوگ اولیه برای ۶۰ روز آینده موجودی آزمایشی می‌سازد.

```bash
npm run setup
# در دو ترمینال جداگانه:
npm run worker
npm run dev
```

اسکریپت setup در صورت نبود `.env`، رمز دیتابیس و کلیدهای مستقل رمزگذاری و امضای callback را تولید می‌کند؛ آن‌ها را چاپ نمی‌کند. فایل `.env`، دیتای محلی و خروجی‌های ساخت در Git قرار نمی‌گیرند. اگر سرویس‌ها را خودتان فراهم می‌کنید، `.env.example` را به `.env` کپی و مقادیر را امن تنظیم کنید؛ سپس:

```bash
npm ci
npm run db:generate
npm run db:migrate
npm run db:seed
npm run worker
# در ترمینال جدا:
npm run dev
```

برنامه روی پورت ۳۰۰۰ اجرا می‌شود. `/api/v1/health` باید سلامت دیتابیس، Redis و heartbeat مربوط به worker را گزارش کند. پرداخت بدون worker در وضعیت تأیید باقی می‌ماند؛ worker را جداگانه اجرا کنید. توقف Docker با `docker compose stop` داده را حفظ می‌کند؛ از حذف volumeهای حاوی داده خودداری کنید.

## تجربه مسیر خرید

۱. از صفحه اصلی، پرواز، هتل یا تور را جستجو کنید. تقویم جستجو شمسی است؛ تاریخ‌ها در دیتابیس به میلادی/UTC ذخیره می‌شوند.
۲. برای پرواز، یک‌طرفه، رفت‌وبرگشت یا چندمسیره انتخاب کنید. مسیرها باید متصل و تاریخ‌ها صعودی باشند.
۳. پیشنهاد را انتخاب، ثبت‌نام و مشخصات **آزمایشی** مسافر را تکمیل کنید؛ مثلاً شماره مدرک `DEMO123456`.
۴. ظرفیت در تراکنش دیتابیس برای ۱۵ دقیقه نگه داشته و مبلغ در سرور دوباره محاسبه می‌شود.
۵. در شبیه‌ساز، پرداخت موفق، شکست پرداخت، انصراف یا «پرداخت موفق/شکست صدور» را انتخاب کنید.
۶. وضعیت مستقل پرداخت، رزرو و صدور را در سفارش ببینید. سند متنی DEMO فقط پس از تأیید تأمین‌کننده قابل دریافت است. تور شیراز به تأیید دستی کارشناس نیاز دارد.
۷. کنسلی سفارش صادرشده، پس از تأیید کارشناس به صف استرداد می‌رود. اعلان‌های داخل حساب، تیکت پشتیبانی و اطلاعات مسافران به دیتابیس متصل‌اند.

واحد ذخیره مبلغ **ریال صحیح** و واحد نمایش **تومان** است. در DEMO نرخ همه سنین یکسان و هر نفر یک واحد ظرفیت است. برای هتل هر اتاق حداکثر دو مهمان دارد و ظرفیت تمام شب‌ها اتمیک بررسی می‌شود.

## مدیریت و نقش‌ها

هیچ حساب مدیر یا رمز عمومی در seed وجود ندارد. ابتدا از رابط ثبت‌نام کنید، سپس اپراتور مجاز محیط می‌تواند حساب ثبت‌شده را ارتقا دهد:

```bash
npx tsx scripts/promote-admin.ts your-registered-email@example.com
```

این عملیات audit می‌شود. نقش از کوکی یا درخواست کاربر پذیرفته نمی‌شود؛ مجوز جاری در هر درخواست از دیتابیس خوانده می‌شود.

| نقش          | دسترسی                                        |
| ------------ | --------------------------------------------- |
| مشتری        | سفارش‌ها، مسافران، اعلان‌ها و تیکت‌های خودش   |
| پشتیبان      | مشاهده سفارش‌ها و پاسخ به تیکت                |
| کارشناس رزرو | مشاهده سفارش‌ها و تأیید دستی                  |
| مدیر فروش    | آمار، سفارش‌ها، تورها، هتل‌ها و تأمین‌کنندگان |
| حسابدار      | خروجی مالی و تأیید استرداد                    |
| مدیر کل      | همه موارد، محتوا، نقش کاربران و audit         |

پنل `/admin`: آمار مبتنی بر داده واقعی همین دیتابیس آزمایشی، نمودار روزانه، سفارش‌ها/مسافران/تاریخچه، ایجاد و ویرایش تور، انتشار یا خروج از فروش، ویرایش محتوای هتل و ظرفیت روزانه، استرداد، CSV قابل استفاده در Excel، پاسخ پشتیبانی، ویرایش مقاله و مدیریت نقش‌ها. کاهش ظرفیت به کمتر از رزروهای موجود رد می‌شود.

## تست و ساخت

```bash
npm test                  # تست سرویس‌ها و API روی دیتابیس جداگانه berjis_test
npm run typecheck
npm run build             # Next.js + worker/migration/seed bundles
npm run test:e2e           # برنامه و worker باید در حال اجرا باشند
npm audit
```

تست‌های دیتابیس به‌صورت پیش‌فرض از دیتابیس محلی `berjis_test` استفاده می‌کنند و به دیتابیس توسعه دست نمی‌زنند. نام دیتابیس تست باید با `_test` تمام شود. برای دیتابیس تست مجزا `TEST_DATABASE_URL` را تنظیم کنید. E2E روی محیط DEMO جاری، حساب و سفارش مخصوص تست می‌سازد و پس از اجرا فقط fixtureهای ثبت‌شده خودش را حذف و ظرفیت را بازمی‌گرداند؛ روی سامانه واقعی اجرا نکنید. Chromium از `/usr/bin/chromium` استفاده می‌شود؛ برای مسیر دیگر `CHROMIUM_PATH` تنظیم کنید. گزارش مرورگر در `playwright-report` و تصاویر در `test-results` ذخیره می‌شوند.
